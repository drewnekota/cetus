# Runtime 折叠规则

折叠用于整理过程，不代表任务完成。所有 runtime 使用同一套分段和展开状态逻辑。

## 各 runtime 的信号

| Runtime | Cetus 使用的信号 | 回复保留方式 |
| --- | --- | --- |
| Codex | `agentMessage.phase`、回合完成事件 | 将 `commentary` / `final_answer` 传到文字块并保存；明确标记的最终回复始终保留 |
| Claude Code | `result`、工具结果、后台任务通知 | 不把 `result` 等同于某个文字块的最终回复标记；使用连续文字兜底规则 |
| OpenCode、Grok、Kimi、DSH | ACP 内容更新、工具状态和 `stopReason` | 使用同一套兜底规则；异常结束与工具状态独立处理 |
| Cetus / pi | 内容、工具事件及 `agent_end` / `agent_settled` | 使用兜底规则；`willRetry` 表示还会继续时保持执行中的显示 |
| 旧会话或缺少 phase 的 Codex | 已保存的文字和工具块 | 使用兜底规则，无需迁移会话数据 |

## 展示规则

- 执行中：文字直接显示，连续思考和工具调用归为可展开的小组。不因某条文字开始输出而把整个过程折叠。
- 结束后：最后一组连续非空文字及其后续操作保留；更早的过程默认折叠。连续文字块可能只是同一段回复的传输分片，不能只保留最后一片。
- 明确的 `final_answer` 文字始终保留，即使后面还有清理操作、补充进度或错误信息。
- 只有工具或思考时，保留最后一个有效操作，折叠更早的过程。工具尾部显示“本轮已结束”，不声称整个任务完成。
- 产物、图片、附件等独立内容始终显示；折叠不跨过这些内容合并前后步骤，保持真实顺序。
- 失败、未收到结果的工具，以及仍在运行的后台子任务单独保留，默认展开操作列表。原始命令和结果详情仍由用户按需展开。
- 父回合结束后，子任务的结构化运行状态仍有效；它继续显示运行状态。普通工具缺少结果则显示“未收到结果”，不显示成功。
- 正常结束或取消时，清理本轮遗留的普通 streaming 标记，避免卡片持续转圈；不会清除子任务的结构化状态。

## 手动展开优先

折叠组和组内工具使用源消息与块位置作为稳定 ID。回合结束、组件重新挂载或过程小组合并时，保留本次应用会话中的手动选择；合并涉及多个已操作小组时，最近一次选择优先。没有手动选择时才应用默认折叠规则。展开选择不保证跨应用重启保存。

## 验证入口

```sh
bun test src/lib/assistant-segments.test.js src/lib/disclosure-state.test.js
cargo test --manifest-path src-tauri/cetus-bridge/Cargo.toml --lib cli_agent::tests
pnpm build
```

分段测试覆盖最终回复、连续文字、工具尾部、纯工具、产物顺序、失败、取消、后台任务、重试及历史回放。桥接测试覆盖 Codex 阶段元数据的流式输出、断开和持久化，并对四个 ACP backend 运行相同的内容与工具更新测试。

实际组件点击验证包括：结束时保留手动展开的过程和工具详情、重新挂载后的状态、未手动操作时的默认折叠，以及后台任务、失败和未收到结果的显示。验证使用本地组件夹具，不会向各模型服务发送真实任务。
